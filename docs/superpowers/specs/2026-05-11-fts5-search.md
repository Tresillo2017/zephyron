# FTS5 Search & Search Page Redesign

**Date:** 2026-05-11
**Status:** Approved, ready for implementation
**Closes:** #19

## Goal

Replace LIKE-based search with D1 FTS5 full-text search across sets, artists, events, and tracks. Redesign the search page with a Top Result hero card, category tabs, and per-entity result sections. Simplify the TopNav by removing the inline search preview dropdown.

### Query pattern

Input query is tokenised for FTS5: multi-word queries are wrapped as a phrase with prefix matching: `john summit` → `"john summit"*`. Single words: `techno` → `techno*`.

```ts
function toFtsQuery(q: string): string {
  const trimmed = q.trim().replace(/"/g, '')
  return trimmed.includes(' ') ? `"${trimmed}"*` : `${trimmed}*`
}
```

### Rewritten `worker/routes/search.ts`

Four parallel D1 queries + top result selection:

```ts
const ftsQ = toFtsQuery(q)

const [setsRows, artistsRows, eventsRows, tracksRows] = await Promise.all([
  env.DB.prepare(`
    SELECT s.id, s.title, s.artist, s.genre, s.duration_seconds, s.cover_image_r2_key, s.play_count,
           s.stream_type, s.youtube_video_id
    FROM sets_fts f JOIN sets s ON f.id = s.id
    WHERE sets_fts MATCH ? ORDER BY rank LIMIT 10
  `).bind(ftsQ).all(),
  env.DB.prepare(`
    SELECT a.id, a.name, a.image_url,
           (SELECT COUNT(*) FROM set_artists sa WHERE sa.artist_id = a.id) as set_count
    FROM artists_fts f JOIN artists a ON f.id = a.id
    WHERE artists_fts MATCH ? ORDER BY rank LIMIT 10
  `).bind(ftsQ).all(),
  env.DB.prepare(`
    SELECT e.id, e.name, e.slug, e.series, e.location, e.year, e.cover_image_r2_key,
           (SELECT COUNT(*) FROM sets s WHERE s.event_id = e.id) as set_count
    FROM events_fts f JOIN events e ON f.id = e.id
    WHERE events_fts MATCH ? ORDER BY rank LIMIT 10
  `).bind(ftsQ).all(),
  env.DB.prepare(`
    SELECT d.id, d.set_id, d.track_title, d.track_artist, d.start_time_seconds, d.confidence,
           s.title as set_title, s.artist as set_artist
    FROM tracks_fts f JOIN detections d ON f.id = d.id JOIN sets s ON d.set_id = s.id
    WHERE tracks_fts MATCH ? ORDER BY rank LIMIT 10
  `).bind(ftsQ).all(),
])
```

**`top_result`**: first result from whichever category has a result, priority order: artists → sets → events → tracks. Shaped as:

```ts
interface TopResult {
  type: 'set' | 'artist' | 'event' | 'track'
  id: string
  title: string
  subtitle: string
  link: string
  image_r2_key: string | null
  tags: string[]
}
```

**Response shape** (replaces current):
```json
{
  "data": {
    "top_result": { ... } | null,
    "sets": [...],
    "artists": [...],
    "events": [...],
    "tracks": [...]
  },
  "ok": true
}
```

### `src/pages/SearchPage.tsx` — full rewrite

**URL params used:**
- `?q=` — search query (synced with search bar input via `useNavigate`)
- `?tab=` — active category: `all | sets | tracks | artists | events` (default: `all`)

**State:**
- `results: SearchResults | null`
- `loading: boolean`
- `activeTab` — derived from `?tab=` URL param

**Sections rendered per tab:**

| Tab | Shows |
|-----|-------|
| `all` | Top Result hero + Sets (4) + Tracks (5) + Artists (4) + Events (3), each with "See all →" link |
| `sets` | Full sets grid (all results) |
| `tracks` | Full track list (all results) |
| `artists` | Full artist grid (all results) |
| `events` | Full events grid (all results) |

**Top Result hero** (shown only in `all` tab, when `top_result` is non-null):
- Large card with cover art / artist avatar (from `image_r2_key` or gradient fallback)
- `type` label e.g. "Top Result · Artist"
- `title` (large, bold)
- `subtitle`
- `tags` (genre chips)
- Navigate button (→ `top_result.link`)

**Sets section**: reuses existing `SetGrid` component.

**Tracks section**: ranked rows — timestamp (accent monospace), track title, "in [set_title] · [set_artist]", confidence percentage badge.

**Artists section**: 4-column grid — avatar (from `image_url` or gradient fallback based on name), name, set count.

**Events section**: 3-column grid — cover image or gradient, event name, location + set count.

**Empty state** (no query): centered search icon + instructional text.

**No results state**: "No results for [query]" message.

## Edge Cases

| Case | Behaviour |
|------|-----------|
| Empty query | Return `{ top_result: null, sets: [], artists: [], events: [], tracks: [] }` |
| FTS5 special characters in query (e.g. `b2b`) | Sanitise: strip `"`, `(`, `)`, `*` before wrapping |
| No results in any category | `top_result: null`, all arrays empty |
| Single-word query | Appended `*` for prefix match (`techno*`) |
| Multi-word query | Wrapped as phrase with prefix (`"john summit"*`) |
| `tags` field is stored as JSON string in artists table | Parse before indexing in FTS, store space-joined in FTS column |
